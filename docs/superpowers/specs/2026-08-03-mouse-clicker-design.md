# Windows 全局鼠标连点器设计

**日期：** 2026-08-03
**状态：** 已获用户确认，待进入实现计划

## 目标

制作一个 Windows 桌面连点器，能够在整个桌面范围内录制用户的鼠标移动和操作，并按录制时的绝对屏幕坐标与原始时间间隔重复回放。程序支持多套模板、固定循环次数和无限循环。

## 已确认范围

- 作用范围：整个 Windows 桌面，而不是单个应用窗口。
- 录制事件：鼠标移动、左键/右键/中键按下与释放、双击、滚轮和按住拖动。
- 时间：保存事件之间的原始时间间隔。
- 坐标：使用录制时的绝对屏幕坐标，并记录整个多显示器虚拟桌面范围。
- 模板：支持多套本地模板，可新建、命名、切换和删除。
- 回放：支持固定循环次数和无限循环。
- 控制：只使用连点器窗口按钮，不使用全局热键。
- 存储：模板只保存在本机，不上传数据。

## 非目标

- 第一版不录制键盘输入。
- 第一版不按窗口相对坐标定位，也不识别按钮、图像或文本。
- 第一版不提供速度倍率、随机轨迹或随机延迟；回放以原始录制速度为准。
- 第一版不添加全局热键。

## 用户流程

1. 用户在模板列表中新建或选择模板。
2. 点击“开始录制”，界面进入倒计时，3 秒后开始监听全局鼠标。
3. 用户在其他软件中执行操作。程序保存每个鼠标事件的类型、坐标和相对于前一事件的时间间隔。
4. 用户回到连点器窗口点击“停止录制”。控制按钮所在窗口范围内的鼠标事件不写入模板，避免录入连点器自身的按钮操作。
5. 模板自动保存，界面显示事件数量和总时长。
6. 用户选择固定循环次数或勾选“无限循环”，点击“开始回放”。
7. 程序按事件序列回放。回放区显示当前循环进度，用户可点击“暂停/继续”或“停止”。
8. 关闭窗口时，程序先停止回放和全局监听，再退出。

## 界面结构

主窗口分为三个区域：

- **模板区**：模板列表，以及新建、重命名、删除按钮。
- **录制区**：当前模板名称、录制状态、事件数量、总时长，以及开始录制/停止录制按钮。
- **回放区**：循环次数输入框、无限循环复选框、当前循环进度，以及开始回放/暂停/继续/停止按钮。

按钮状态必须反映当前状态：录制时不能开始回放，回放时不能修改模板，暂停时只能继续或停止。非法循环次数、空模板和损坏模板都不能进入回放。

## 组件与职责

### `models.py`

定义 `MouseEvent`、`Template`、`ScreenGeometry` 和回放配置的数据结构，负责字段校验以及从字典读写。

### `recorder.py`

使用全局鼠标监听器接收移动、按键和滚轮回调。用单调时钟计算 `delay_ms`，不使用系统日期时间作为计时依据。录制状态由线程安全的状态对象维护，并过滤连点器窗口矩形内的控制事件。

### `player.py`

在后台线程中执行模板回放。对每个事件先等待对应的延迟，再注入鼠标事件；等待过程响应暂停和停止信号。循环完成后根据配置开始下一轮，停止时立即结束并通过线程安全消息更新界面。

### `windows_input.py`

封装 Windows 输入注入和屏幕信息：用 Windows API 获取虚拟桌面起点、宽度、高度，用 `SendInput`/对应鼠标标志注入移动、按键和滚轮事件。这个模块提供可替换的输入后端，方便单元测试不触碰真实鼠标。

### `storage.py`

在 `%APPDATA%\\MouseClicker\\templates` 下按 UUID 保存每套模板的 JSON 文件，提供列表、读取、保存、重命名和删除操作。写入采用临时文件替换，避免程序异常时留下半个 JSON 文件。

### `app.py`

创建 Tkinter 主窗口，连接录制器、播放器和存储层。后台线程不直接更新 Tkinter 控件，而是通过线程安全队列将状态消息交给主线程轮询处理。

## 模板数据格式

模板文件使用版本化 JSON。示例：

```json
{
  "version": 1,
  "id": "7f6e8e32-5c5f-4e9a-9c7e-1c3bf3b0ab10",
  "name": "网页操作",
  "screen": {
    "left": -1920,
    "top": 0,
    "width": 3840,
    "height": 1080
  },
  "events": [
    { "type": "move", "x": 520, "y": 340, "delay_ms": 0.0 },
    { "type": "button", "action": "press", "button": "left", "x": 520, "y": 340, "delay_ms": 118.4 },
    { "type": "button", "action": "release", "button": "left", "x": 520, "y": 340, "delay_ms": 64.1 },
    { "type": "scroll", "dx": 0, "dy": -1, "x": 520, "y": 340, "delay_ms": 210.0 }
  ]
}
```

双击由两次按下/释放事件和其时间间隔自然表示；拖动由按住按键期间的移动事件表示。事件延迟保留小数，避免不必要地丢失录制时序。

## 回放与边界行为

- 固定循环次数必须是大于 0 的整数；无限循环与固定次数互斥。
- 空模板不能回放。
- 回放前比较当前虚拟桌面几何信息与模板信息；不一致时显示警告，由用户选择取消或继续。
- 绝对坐标允许落在虚拟桌面的负坐标区域，不强制转换为主显示器坐标。
- 暂停不会丢失当前事件；继续后从剩余事件延迟处继续。
- 停止会取消当前等待、结束循环，并释放可能处于按下状态的鼠标按钮，避免鼠标卡在按下状态。
- 回放异常时显示错误、恢复所有按钮状态，并保留模板文件。

## 测试策略

- `models.py`：测试事件和模板的序列化、必填字段校验、空事件模板和非法循环配置。
- `storage.py`：测试新建、保存、重新读取、重命名、删除，以及损坏 JSON 的错误提示。
- `player.py`：使用记录调用顺序的假输入后端，测试延迟顺序、固定循环、无限循环的停止、暂停/继续和异常释放按键。
- `recorder.py`：使用模拟监听回调测试时间间隔、事件转换和过滤控制窗口区域。
- Windows 集成验收：实际录制一段移动、左键点击、双击、右键、滚轮和拖动，再回放并人工核对位置、顺序和循环行为。

## 验收标准

1. 能在 Windows 桌面上全局录制并保存鼠标移动、点击、滚轮和拖动。
2. 回放使用绝对坐标，并按保存的时间间隔执行。
3. 至少可以同时保存两套模板，并能切换、重命名、删除和再次加载。
4. 固定循环次数和无限循环都能工作，停止按钮能中断回放。
5. 录制和回放状态不会卡住界面；关闭窗口不会留下活动监听器或鼠标按下状态。
6. 自动化测试覆盖核心数据、存储和回放控制逻辑，Windows 集成验收覆盖真实输入链路。
