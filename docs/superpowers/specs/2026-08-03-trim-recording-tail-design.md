# 录制末尾三秒自动排除设计

**日期：** 2026-08-03
**状态：** 已获用户确认，待进入实现计划

## 目标

录制结束时，以用户点击“停止录制”的时刻为终点，自动排除最后 3 秒内的鼠标事件，使返回连点器窗口、准备停止录制的收尾动作不会进入后续循环。

## 已确认行为

- 裁剪时机：停止录制时立即裁剪并保存，不在回放时临时裁剪。
- 裁剪长度：固定 3000 毫秒，不增加 UI 设置项。
- 时间基准：从本次录制开始到点击停止录制的单调时钟时长。
- 保留规则：事件相对于录制开始的时间点小于 `录制总时长 - 3000ms` 时保留；位于或超过截止点的事件排除。
- 如果录制总时长不超过 3 秒，保存空模板；空模板不能开始回放。
- 裁剪后不补充人工等待事件，模板只回放保留下来的事件序列。
- 多模板、绝对坐标、固定/无限循环和窗口按钮控制保持不变。

## 数据流

```text
全局鼠标回调
    -> RecordingSession 保存事件、事件偏移时间和录制总时长
    -> stop 时生成 RecordingResult
    -> 按停止时刻倒推 3000ms 过滤事件
    -> TemplateStore 保存过滤后的事件
    -> PlaybackEngine 按原有序列循环
```

## 组件变更

### `recorder.py`

增加不可变的 `RecordingResult`，包含：

- `events`：原始 `MouseEvent` 列表。
- `event_times_ms`：每个事件相对于录制开始的时间点，和 `events` 一一对应。
- `duration_ms`：从 `start()` 到 `stop()` 的完整单调时钟时长。

`RecordingSession.start()` 保存开始时间；每次接收有效事件时保存当前偏移时间。过滤连点器窗口的事件不会更新事件偏移时间，但录制总时长仍继续增长。`GlobalMouseRecorder.stop()` 在停止监听前取得停止时刻，避免监听器 join 的少量耗时改变裁剪终点。

增加纯函数 `trim_recorded_tail(result, tail_ms=3000.0)`，根据 `event_times_ms` 过滤事件，返回可直接保存的事件列表。该函数拒绝负的裁剪长度，并允许 0 毫秒表示不裁剪，便于测试。

### `app.py`

停止录制时接收 `RecordingResult`，调用 `trim_recorded_tail(result)`，只把过滤后的事件写入模板。状态栏显示“录制完成，已排除末尾 3 秒，保存 N 个事件”，模板事件数和时长显示过滤后的实际循环内容。

### `models.py`、`player.py`、`storage.py`

不改变模板 JSON 格式、回放接口和存储接口。原始事件偏移时间只在本次录制裁剪过程中使用，不写入模板文件。

## 边界与错误处理

- 录制只有一个事件且总时长超过 3 秒时，如果该事件发生在末尾 3 秒内，则过滤后为空模板。
- 停止前没有有效事件时仍返回完整录制时长，模板保存为空。
- 事件时间数组和事件数组长度不一致时抛出 `ValueError`，不保存不完整结果。
- 录制总时长小于 0 的异常时钟值按 0 处理，不产生负截止点。
- 存储失败时保留原模板文件，不用部分裁剪结果覆盖旧数据。

## 测试策略

- `RecordingSession` 测试开始时间、停止时长、事件偏移时间和排除窗口不影响总时长。
- `trim_recorded_tail` 测试：保留截止点之前的事件、排除截止点上的事件、总时长不足 3 秒、0 毫秒和非法负裁剪长度。
- `GlobalMouseRecorder` 测试确认停止时刻在 listener 停止前被捕获，并返回 `RecordingResult`。
- 运行现有全套自动化测试，确认模板序列化、播放器循环和 UI 状态没有回归。
- 启动 exe 做一次 UI 烟雾测试；真实鼠标端到端操作仍由用户首次录制自己的模板时验收。

## 验收标准

1. 录制 10 秒并在第 8 秒后继续等待到第 10 秒再停止时，第 7 秒及之后的事件不进入模板。
2. 录制不足 3 秒时模板为空且“开始回放”不可用。
3. 连点器窗口中的停止按钮仍不会被录入，但从目标软件返回连点器的最后 3 秒动作会被统一排除。
4. 模板列表、循环次数、无限循环、暂停/继续/停止和 exe 启动行为保持原样。
